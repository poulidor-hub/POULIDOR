Ajouter une application

Objectif

Installer une nouvelle application dans le parc depuis son dépôt git.

Quand l'utiliser

À la mise en service d'une nouvelle application.

Voies possibles

1. Fichier seed (recommandé)

Décrire l'app (slug + URL git) dans un YAML puis laisser hubctl faire : clone, détection de la config, écriture du .env, build, démarrage et synchronisation du coffre.

./hubctl seed apps.yaml        # déploie ou converge les apps listées
./hubctl seed apps.yaml --dry-run   # simuler d'abord

2. Clonage manuel

  1. git clone <URL> APPS/<nom> (ex. git@github.com:Poutchouli/exemple-app-2.git).
  2. Lancer INITIALISE.py depuis le dossier de l'app.

3. Assistant IA

Demander à l'agent (« Crée une app … ») : le skill create-hub-app orchestre toute la création.

Contenu de démo Par défaut, INITIALISE.py nettoie le contenu de démonstration. Lancez-le avec --demo pour le conserver et explorer l'app (--yes pour un mode non interactif).
En coulisse (technique)

Le clone hérite des droits SSH du serveur et atterrit dans APPS/<nom-du-dépôt>. INITIALISE.py exécute 14 étapes (.env, docker-compose, config, frontend, tests, VERSION, CHANGELOG). Une garde disque s'applique.

⚠ Points d'attention
  • Vérifiez l'espace disque avant un gros clone (refus sous 5 % libre).
  • Le nom du dossier vient du nom du dépôt : choisissez un dépôt bien nommé.
En cas de problème

Échec du clone : vérifiez l'URL et les droits SSH du serveur (ou configurez le dépôt depuis l'UI HUB, vue Santé → « Configurer le dépôt git »). Échec de INITIALISE.py : relancez-le manuellement depuis le dossier de l'app.
