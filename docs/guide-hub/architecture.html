Architecture du parc

Référence des composants qui constituent le HUB POULIDOR.

Vue d'ensemble

POULIDOR/
├── hubctl → hubctl_src/     ← CLI de pilotage (menu, coffre, export/restore, socle)
├── HUB_base/                ← Hub SSO (auth JWT/JWKS/OIDC, annuaire, messagerie, backups)
├── HUBsocle/                ← socle applicatif versionné des apps (factory + images de base)
├── HUBapp_TEMPLATE_base/    ← template canonique de toute nouvelle app
├── APPS/                    ← applications (production + ateliers -ws)
└── exports/                 ← archives export du parc

Le Hub central (HUB_base/)

  • Authentification : émet des jetons JWTJSON Web Token : jeton de session signé, présenté par l'utilisateur à chaque app. vérifiés par les apps via JWKSJSON Web Key Set : les clés publiques exposées par le Hub pour vérifier les jetons..
  • Annuaire (registry) : les apps s'y enregistrent automatiquement au démarrage.
  • Messagerie : notifications entre apps et vers les utilisateurs.
  • Sauvegardes : backup quotidien automatique du Hub.

Le template (HUBapp_TEMPLATE_base/)

Modèle de référence pour créer une app : backend FastAPI, frontend React + Vite, PostgreSQL, Docker Compose. Copié par create_app.sh puis personnalisé par INITIALISE.py.

Le socle versionné (HUBsocle/)

Le code de base des apps est progressivement mutualisé dans un socle versionné : factory create_app(), paquets hub-socle (pip) et @poulidor/hub-socle (npm), images de base poulidor/socle-api / socle-web construites localement (./hubctl socle build, offline-first). Chaque app du socle déclare sa version via APP_SOCLE_VERSION (./hubctl socle status = drift de la flotte). Les apps existantes restent des forks du template ; les nouvelles apps naîtront « fines » via INITIALISE v2 (à venir).

Production vs Atelier

InstanceRôleSlug
APPS/X (projet compose défaut)App en productionnom normal
APPS/X (2ᵉ projet compose -p X-ws)Atelier de développementsuffixe -ws

L'atelier est distingué par APPS/X/.workshop.env (ports, subnet et ref git dédiés) : prod et atelier coexistent sur le même serveur. Voir Atelier (workshop).

Le coffre

Stockage chiffré (FernetChiffrement symétrique authentifié : les secrets ne sont lisibles qu'avec la passphrase.) des secrets du parc, dans hubctl_src/hubctl_cli/vault/parc.vault.enc. Voir la page Coffre.

export du parc

Archive complète du parc (tar.gz chiffrée) pour migration ou sauvegarde hors-ligne. Voir la page export / restore.
