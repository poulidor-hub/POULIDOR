Bienvenue dans le guide du HUB POULIDOR

Ce guide forme à l'usage du HUB : un parc d'applications web reliées à un service d'authentification central. Tout le pilotage se fait depuis un seul outil en ligne de commande : ./hubctl.

En une phrase Le HUB héberge plusieurs applications qui partagent la même connexion (authentification unique), et hubctl est le tableau de bord qui permet de les installer, démarrer, sauvegarder et dépanner.

Comprendre le parc en 5 minutes

POULIDOR/
├── hubctl                   ← l'outil de pilotage (ce que vous lancez)
├── HUB_base/                ← le Hub central (connexion, annuaire des apps)
├── HUBapp_TEMPLATE_base/    ← le modèle pour créer une nouvelle app
├── APPS/                    ← les applications (production + ateliers -ws)
└── exports/                 ← les archives du parc
  • Hub central : gère la connexion (SSOSingle Sign-On : une seule connexion donne accès à toutes les apps du parc.), l'annuaire des apps et les sauvegardes.
  • Applications : les logiciels métier, chacun dans son dossier sous APPS/.
  • Atelier : copie d'une app (2ᵉ projet Docker Compose -p X-ws, même dossier APPS/X/) pour développer sans toucher à la production.
  • Coffre : stockage chiffré des secrets (mots de passe, clés) du parc.

Les deux modes de travail

ModeCiblePour quoi faire
PRODUCTIONLes apps APPS/XUsage réel, quotidien.
DÉVELOPPEMENTLes ateliers -wsTester des modifications sans risque.

Le mode est auto-détecté : DEV dès qu'un atelier est actif (.workshop.env), PROD sinon — et on peut le forcer avec --dev/--prod. Voir Modes DEV/PROD.
