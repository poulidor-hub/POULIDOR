Prendre en main hubctl

hubctl est le poste de pilotage du parc : un menu interactif lancé dans le terminal du serveur.

Lancer l'outil

./hubctl              # menu interactif (avec intro animée)
./hubctl --no-anim    # sans l'intro animée
./hubctl --dry-run    # affiche les commandes sans les exécuter
./hubctl --init       # clone les dépôts manquants du parc
Astuce --dry-run est idéal pour découvrir sans risque : rien n'est réellement exécuté.

Se déplacer dans le menu

ToucheAction
↑ ↓Naviguer entre les entrées
EntréeValider l'entrée sélectionnée
ÉchapRevenir au menu précédent, ou quitter depuis le menu principal
Ctrl+CInterrompre l'action en cours et revenir au menu

L'arbre du menu

ToucheMenuContient

2HubUpdate hub · Réparer/Diagnostiquer · Start/Stop HUB · Apps (Vue+Disque) · Logs hub
3ConfigurationQuick setup · Réseau · Admin · Mode & avancé · Coffre · Workshop*
4ScénariosQuick diag · Full update · App rescue · Health check
5BasculePasser en DEV / en PROD
0Quitter—

* Workshop n'apparaît qu'en mode DÉVELOPPEMENT.

Les garde-fous

hubctl vous protège
  • Chaque action destructrice demande une confirmation Oui/Non.
  • Une app supprimée part en corbeille (hubctl_cli/_trash/), jamais un rm -rf.
  • Une archive tar.gz est créée avant toute suppression.
  • Garde disque : avertissement sous 15 % d'espace libre, refus sous 5 %.
En coulisse (technique)

Les opérations s'appuient sur les Makefile du parc : make -C HUB_base … pour le hub central et make -C APPS/<nom> … pour les apps. Au premier lancement, hubctl crée un environnement Python (hubctl_cli/.venv) et installe rich et cryptography. Sans terminal interactif (pipe, cron), il affiche l'état du hub puis quitte.
