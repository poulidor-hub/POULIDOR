export / restore : l'archive du parc

Objectif

Exporter tout le parc (ou une seule app) dans une archive tar.gz chiffrée, et la restaurer sur un autre Hub.

Quand l'utiliser

Migration vers un nouveau serveur, sauvegarde hors-ligne complète, transfert vers un environnement de test.

Commandes

./hubctl export                       # tout le parc → tar.gz chiffré
./hubctl export --app exemple-app          # une seule app
./hubctl export --no-encrypt          # non chiffré (legacy, secrets en clair)
./hubctl export --passphrase-stdin    # passphrase via stdin (CI / DR)
./hubctl restore park-*.tar.gz        # restauration (Hub vierge uniquement)
Anciens noms — les commandes s'appelaient park-export / park-restore. Elles se nomment désormais export / restore.

Restauration PRA : pra-restore

Pour reprendre l'activité depuis un kit de secours (coffre + dernier snapshot, cf. Coffre → Emplacement PRA) :

./hubctl pra-restore                  # assistant interactif (scan auto du kit)
./hubctl pra-restore /mnt/kit --yes   # non interactif

Fanions : --snapshot (choisir le snapshot), --apps all|none|a,b, --admin-user, --yes, --dry-run.

⚠ restore : Hub VIERGE uniquement restore ne fonctionne que sur un Hub neuf, sans données (pas d'écrasement d'un parc existant). pra-restore peut s'exécuter sur un parc non vide uniquement avec --force (explicite, à ne utiliser qu'en pleine conscience).
En coulisse (technique)

L'export empaquette le code, les .env et les données des volumes, chiffrés par passphrase. La restauration refuse de s'exécuter si le Hub contient déjà des données, pour éviter tout écrasement accidentel. L'assistant pra-restore : détecte le kit → passphrase du coffre → restaure secrets/.env → build & start de la stack → injection du snapshot → sélection des apps à rebuilder/réinjecter.

En cas de problème

Si restore refuse de s'exécuter, c'est que le Hub cible n'est pas vierge : repartez d'une installation neuve du Hub. Passphrase d'archive refusée : vérifiez la casse ; en CI, utilisez --passphrase-stdin.
