Commandes make du parc

Le parc possède deux familles de Makefile :

  • HUB_base/Makefile — pour le hub central (api, db…).
  • le Makefile d'app (hérité du template HUBapp_TEMPLATE_base), présent dans chaque APPS/<nom>.

Les commandes se lancent depuis le dossier concerné, ou via make -C <dossier> <cible>. Dans chaque Makefile, make help (ou make sans cible) liste les cibles disponibles.

HUB_base/Makefile — hub central

À lancer depuis HUB_base/ (ou make -C HUB_base <cible>).

CommandeRôle
make buildConstruit les images Docker du hub.

make up-devDémarre le hub en mode développement (avant-plan, via docker-compose.dev.yml).
make downArrête les services du hub.
make logsSuit les logs (dernières 100 lignes).
make psListe les conteneurs et leur état.
make testSuite de tests parallélisée (pytest, DB de test isolée).
make test-seqSuite de tests séquentielle (déterministe).
make test-covTests avec rapport de couverture.
make test-dockerpytest dans le conteneur hub-api.

Le Makefile du hub compte 10 cibles : 6 d'exploitation + 4 de tests.

Le Makefile d'app

Valable pour chaque app dans APPS/, hérité de HUBapp_TEMPLATE_base/Makefile. À lancer depuis le dossier de l'app.

SSL & environnement

CommandeRôle
make sync-envAlloue les ports via le Hub (allocate_ports.py) et synchronise FRONTEND_HTTPS_PORT + APP_VERSION dans le .env. À lancer après toute modif du .env ou de VERSION.
make update-envAprès une montée de version du template : fusionne les nouvelles clés du .env.example dans le .env existant (sauvegarde horodatée auto, valeurs existantes et clés propres à l'app préservées). Fusion, jamais régénération.
make sync-hub-hostSynchronise l'adresse IP du Hub dans le .env de l'app (découverte auto, ou forcer : make sync-hub-host HUB_HOST=192.168.x.x). Utile après un changement d'IP du serveur.
make sslGénère les certificats SSL locaux (scripts/generate-ssl.sh).

Cycle de vie

make downArrête tous les services (prod ou dev).

Nettoyage

Attention aux commandes de nettoyage
  • make clean supprime les conteneurs, les volumes et les caches : les données de l'app sont perdues.
  • make clean-all supprime en plus les images Docker.
Ne les utilisez que si vous avez une sauvegarde ou si l'app n'a pas de données importantes.

Hors make, pas sur hubctl

Quelques scripts du parc ne sont exposés ni par hubctl ni par un Makefile :

CommandeRôle
bash scripts/create_app.sh <nom>Scaffolde une nouvelle app en copiant HUBapp_TEMPLATE_base dans APPS/<nom>.
bash scripts/test_flux_complet.shTest d'intégration Hub + app en isolation totale (Hub de test sur ports +18000, ressources préfixées pouly-test).
cd HUBCSS && npm run buildReconstruit le design system (dist/). Source de make refresh-design-seed côté app.
cd HUBCSS && npm run demo:devDémarre le playground de démo du design system.
Sous le capot des make make sync-env appelle ACTIONS/PYTHON/allocate_ports.py (réservation de ports auprès du Hub) et make init appelle ACTIONS/PYTHON/INITIALISE.py. Vous n'avez normalement pas à les lancer directement.
En coulisse (technique)

Ces cibles enveloppent docker compose. make dev équivaut à un rebuild suivi d'un up en avant-plan. make sync-env interroge le Hub pour réserver des ports uniques avant de réécrire le .env.
