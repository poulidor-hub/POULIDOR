Supprimer une application

Objectif

Retirer une application du parc — suppression définitive : le seul filet de sécurité est l'archive tar.gz créée avant le retrait du dossier.

Quand l'utiliser

Quand une app n'est plus utilisée, ou pour la réinstaller proprement.

Comment faire

La suppression passe par hubctl app remove : arrêt avec volumes (down -v), sauvegarde automatique, puis retrait du dossier de l'app — après confirmation.

./hubctl app remove <slug>             # supprime l'app (confirmation interactive)
./hubctl app remove <slug> --dry-run   # voir d'abord ce qui serait supprimé

Le déroulé : compose down -v (conteneurs et volumes, base incluse), puis backup tar.gz de l'app, puis retrait du dossier APPS/<slug> (définitif). Répondre O pour confirmer ; --yes passe la confirmation (scripts, CI).

En coulisse (technique)

hubctl arrête d'abord le projet compose avec ses volumes (down -v), crée ensuite une archive tar.gz du dossier dans hubctl_src/hubctl_cli/backups/ (chmod 600, best-effort), puis supprime APPS/<slug> définitivement (rm -rf) — le coffre n'est jamais touché (hubctl 0.24.0).

⚠ Points d'attention
  • down -v détruit les volumes Docker : les données de la base sont perdues — le backup tar.gz n'archive que le dossier de l'app (code, config, .env), pas les volumes. Un dump préalable (ex. pg_dump) est nécessaire si ces données comptent.
  • Les archives s'accumulent dans hubctl_src/hubctl_cli/backups/ : pensez à l'espace disque.
  • La commande agit sur une seule app : relisez le slug demandé avant de confirmer.
En cas de problème

Pour remonter une app supprimée par erreur : réinstallez-la depuis son dépôt git (./hubctl app install <url-git>) — l'archive tar.gz de hubctl_src/hubctl_cli/backups/ rend son code et sa configuration, pas les données des volumes (détruites par down -v) : celles-ci ne survivent que si un dump avait été fait avant la suppression.
