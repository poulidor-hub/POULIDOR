Workshop : atelier ↔ production

Objectif

Déplacer une application entre la production (APPS/) et l'atelier (APP_Workshop/) pour développer ou tester avec une copie des données réelles, puis remettre les modifications en production.

Quand l'utiliser

Quand vous voulez modifier une app sans risque pour la version en service. Disponible uniquement en mode DÉVELOPPEMENT.

Étapes dans hubctl

  1. Passer en mode DEV : menu principal → 5.
  2. Configuration (3) → Workshop (6).
  3. Choisir [→] mettre en atelier ou [←] remettre en production.
  4. Confirmer Oui.
En coulisse (technique)

La mise en atelier fait un docker compose down, copie le code vers APP_Workshop/<app>-ws, clone le volume DockerStockage persistant de la base de données, séparé du conteneur. de la base via un conteneur Alpine, réécrit le slug en -ws dans le .env, puis redémarre. Le retour en production applique le flux inverse (les modifications de la base sont ramenées).

⚠ Points d'attention
  • Le mode DEV est obligatoire pour voir le menu Workshop.
  • Le clone recopie les données réelles de la base : traitez l'atelier avec le même soin.
  • Le slug change (-ws) : les ports et l'URL diffèrent de la prod.
En cas de problème

Si le déplacement échoue en cours de route, l'app source reste intacte (une sauvegarde est prise avant suppression). Vérifiez l'espace disque (2 → Apps Vue+Disque) et relancez.
